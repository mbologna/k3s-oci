# Design

## Free allowance

A Pay As You Go tenancy gets 3,000 A1 OCPU-hours and 18,000 GB-hours a month free (Oracle's
price list, parts B93297 and B93298): 4 OCPU / 24 GB around the clock. A tenancy that was never
upgraded gets half. The rest of the budget: 200 GB of block storage (boot volumes included),
5 volume backups, one network load balancer, one 10 Mbps flexible load balancer, one MySQL
HeatWave system on the MySQL.Free shape (50 GB), Object Storage (10 GB Standard + 10 GB
Infrequent Access + 10 GB Archive on paid tenancies, 50,000 requests a month). `checks.tf` warns
when a plan exceeds the A1, block or MySQL allowance (`a1_free_ocpus`, `a1_free_memory_gbs`).

## Topology

Two k3s servers of 2 OCPU / 12 GB, both running workloads, on kine with MySQL.Free as the
datastore. Losing or rebooting one server keeps the Kubernetes API (the other server, behind the
internal load balancer), the ingress (every node is an NLB backend) and the Longhorn volumes (two
replicas on different nodes) up.

| Layout | Why not the default |
|---|---|
| 3 servers with embedded etcd (`datastore = "etcd"`) | etcd's fsync load on the boot volumes it shares with images and Longhorn, the main failure mode of the earlier single-server design; a third node of overhead; smaller boot volumes (fewer IOPS) |
| 1 server, 4 / 24 | The most room for apps and the simplest, but every reboot is an outage |
| 1 server + 1 agent (the earlier design) | The server is a single point of failure |

The database is the one shared dependency: MySQL.Free has no HA option. Its outage stops the API
(pods keep running); Oracle backs it up daily (one day kept).

## Operating systems

All three are image-based (read-only `/usr`, atomic updates with rollback) and run the same node
script; only the delivery and the update mechanism differ.

| | openSUSE Leap Immutable (default) | Fedora CoreOS | Flatcar Container Linux |
|---|---|---|---|
| Config delivery | cloud-init runs the script from user_data | Ignition fetches it (pre-authenticated request) | Ignition fetches it, and lays down the k3s sysext |
| k3s | installer, `k3s-selinux` staged with transactional-update | installer, `k3s-selinux` layered with rpm-ostree | system extension from the Flatcar sysext bakery |
| First boot | one reboot into the staged snapshot | reboots into the cluster's FCOS release | none |
| SELinux policy for k3s | k3s-selinux, enforcing | k3s-selinux, enforcing | none (the sysext ships no policy) |
| OS updates | `zypper patch` into a new snapshot: security daily, the rest Tue-Thu; kured reboots | the `fcos-os` upgrade Plan rolls the pinned release out, drained, one node at a time (OpenShift's model) | update_engine downloads, kured reboots |
| k3s updates | system-upgrade-controller Plans | system-upgrade-controller Plans | systemd-sysupdate within the minor; a new minor is a new `k3s_version` and node replacement |
| Backing | SUSE (built from SLES 16), 24-month minors | Fedora / Red Hat | the Flatcar team at Microsoft, CNCF incubating |

openSUSE is the default for its lifecycle and backing, enforcing SELinux and the clean split of
security from routine patches that zypper's categories give kured. Ubuntu and openSUSE Leap
Minimal, which the earlier design ran, are not offered: they are mutable and patched in place.

## Components

| Layer | Choice | Notes |
|---|---|---|
| Bootstrap | One bash script per node (files/), rendered by Terraform: OS preparation, the k3s config drop-in, the CAs, k3s, and on the first node Argo CD (Helm, once) | Terraform needs no network path to the nodes |
| Cluster CAs | Generated by Terraform (`ca.tf`), seeded before k3s's first start | An admin kubeconfig output without fetching anything from a node; a rebuild keeps its CA |
| GitOps | Argo CD and the App of Apps (`gitops_repo_url`); k3s's deploy controller applies the App of Apps, the repository credentials and the ClusterIssuers | `gitops/apps/argocd.yaml` adopts the Helm release |
| Ingress | Traefik DaemonSet on NodePorts 30080/30443 | The free NLB preserves client IPs (`externalTrafficPolicy: Local`) |
| Storage | Longhorn, 2 replicas | Backup target: the module's bucket, with your bucket-scoped key |
| Reboots | kured with the security / routine sentinels | Fedora CoreOS: the fcos-os Plan instead |
| NetworkPolicy | k3s's built-in controller, default-deny namespaces in `gitops/network-policies/` | Pods are kept away from the metadata service |
| Monitoring | OCI alarms on `instance_status` and `UnhealthyBackendsPerNlb`; an APM REST monitor | Outside the cluster, free |

## Network

- VCN with a public subnet (the NLB only) and a private subnet (nodes, internal LB, database,
  Bastion endpoint). An empty security list replaces OCI's default one; network security groups
  do the filtering. The private subnet's list adds the Bastion endpoint's egress (6443, 22),
  since Bastion takes no NSG.
- The NLB preserves client IPs, so the NodePort rules allow `0.0.0.0/0`. The nodes have no
  public IPs.
- Pods use 10.42.0.0/16 and services 10.43.0.0/16; keep the VCN outside both.
- The instance metadata service (`169.254.169.254`) is also the VCN's DNS resolver: block port
  80 from pods, never 53.
